StockMind AI

A finance desk of AI agents for a small café

Checks every supplier invoice against what was delivered and agreed, drafts payments only when everything matches, and explains what is eating the margin, with a source for every number.

Synthetic data · Kafe „Plava Šolja“, Belgrade · RSD · Not financial advice

The problem

A café owner pays invoices nobody checked

  • Supplier invoices, delivery notes, a POS export and monthly bills, but no finance team
  • Over-invoiced quantities, prices above the agreed list and expired goods get paid by default
  • Supplier price rises and new costs quietly turn a profitable month into a loss
  • User: the owner or bookkeeper of a small café or shop
  • Data: 7 invoices + 7 delivery notes (PDF), 2.000 POS rows, agreed purchase prices, recipes, monthly costs
  • Output: a payment draft (never sent), held invoices with claims, and this week's priorities
Architecture

20 agents start at once on one shared state

 t=0 ──┬─ Stock Analyst ─────────┐   code-computed rows: stock vs deliveries
       ├─ Sales Analyst ─────────┤   weekly demand per product
       ├─ Margin & Cost Analyst ─┤   price rises, margins, P&L, cost changes
       ├─ Invoice Clerk 01 ──┐   │
       ├─ Receiving Clerk 01 ┴─ three-way match ─ held? ─> Claims Writer 01
       │        …  7 invoice / delivery-note pairs, all in parallel  …
       └─ Receiving Clerk 08 ┴─ three-way match ─ held? ─> Claims Writer 08
                                 │
             all specialists in ─┴─> Reviewer ─> payment decision ─> human --approve

  Mozaik RuntimeState holds every result · a Monitoring participant reacts to
  model.answer events and starts the agents that depend on them
Genuine concurrency

The agents really overlap

  • All analysts and clerks are launched together; a rate-limited queue spaces calls to the free tier
  • A pair's match and claim start the moment its two clerks answer, while others still work
  • The Reviewer is triggered by the event that the last specialist finished
  • Live dashboard: npm run demo → every loop as a bar on a timeline

Illustration of the timeline shape; the real one is in the dashboard and in out/review.md.

Checks between agents

No agent is trusted alone

Two clerks, two documents

The invoice clerk and the receiving clerk read different PDFs; code compares their readings with each other and with the agreed prices.

Every value is quoted

Each value carries a verbatim quote that must be a whole printed row of the document, and amounts must appear as printed ("175,00").

Every figure is sourced

Analysts, the reviewer and claims may only use figures from the rows they cite; anything else is rejected and listed in the report.

Fails closed: a misread holds an invoice, it never pays it. A large clean invoice still waits for a human: --approve can't release a held one. A supplier's corrected invoice is read by a new clerk and matched again against the same delivery note, which is never replaced.

Try it

Runs from the README on a free Gemini key

npm install
cp .env.example .env        # GEMINI_API_KEY=…
npm run demo                # live dashboard on http://127.0.0.1:3000
npm run dev -- --approve F-ZP-2026-01184   # act as the human approver
npm test                    # unit tests, no API calls

Outputs out/review.md (every hold with evidence, findings, reviewer actions, agent timeline) and out/payment-draft.csv (draft, not sent).
